# FastGPT工作流生成助手 v1.1.0

把 AI 应用、Agent 和自动化工作流都当作可版本化、可测试、可回滚的软件系统。先判断任务模式，再决定是否需要知识库、模型、工具、状态或人工审批。使用目标平台导出物或已登记模板作为结构来源；没有用户导出文件时继续生成候选 JSON，而不是阻塞开发。优先使用确定性规则处理确定性问题，用工具读取或改变外部状态，用知识检索提供受控依据，用模型完成必要的理解与表达。

通用节点与平台能力优先参考 FastGPT 官方文档；目标实例的版本、可用模型、资源绑定和实际行为以脱敏导出物、导入结果和运行验证为准。

## 版本与更新

- 当前版本：`1.1.0`，发布日期：`2026-08-11`。
- 保持机器名 `fastgpt-workflow-assistant` 和技能目录名稳定；只更新展示版本和目录内容，不按版本创建多个同名能力 Skill。
- 用户询问当前版本、是否有更新、如何更新或回滚时，读取 [references/版本与更新.md](references/版本与更新.md)，并运行 `scripts/check_skill_version.py` 读取 `assets/skill-version.json`。不要只凭 ZIP 文件名判断版本。
- GitHub 公开版使用仓库根目录 `latest.json` 和 GitHub Release 附件作为版本事实来源；发布者配置仓库地址后，使用稳定的 `/releases/latest/download/latest.json` 检查最新版本。
- 更新必须由用户显式发起。下载新版后校验技能名、版本、ZIP 根目录和 SHA-256，备份当前版本，再通过客户端重新导入或覆盖同一技能目录；完成后重新读取版本并运行离线自测试。
- 不静默下载、安装或覆盖 Skill；无法取得可信发布清单时，只报告当前版本和人工更新方法。

## 执行不可跳过的规则

1. 新建工作流时不要求用户先导出基线。按“目标版本已验证模板 → 兼容模板 → 浏览器在测试应用创建/导入并回读 → 候选 JSON + 用户导入反馈”顺序推进。只有模板不覆盖目标版本、无法访问平台且导入错误不足以定位时，才请求用户提供脱敏导出物。
2. 涉及版本、节点参数或平台能力时，读取 [references/官方文档索引.md](references/官方文档索引.md) 和 [references/版本与兼容性.md](references/版本与兼容性.md)。发现文档、Skill 与实例行为不一致时，以目标实例导出结构和实际执行结果为准，并记录漂移。
3. 修改后执行离线校验；能够访问测试实例时，继续完成导入、重绑、保存、回读/重导出和对应触发方式的运行回归。结构校验通过不等于运行正确。
4. 凭据只放入平台密钥、凭据系统或受保护变量。不得把真实密钥、Token、私有地址、生产数据写入 Skill、样例、日志或发布说明。
5. 测试可能产生外部写入、通知、删除、发布或其他副作用的节点前，说明影响并取得用户授权。只读查询也要明确测试环境和数据范围。
6. 对导入、保存或发布后的工作流重新读取实际状态，验证节点、连线、资源绑定和模型未发生意外漂移。

## 先判定任务模式与实现方式

先选择一个主要模式；混合项目再声明次要模式。不得默认选择 RAG：

- `deterministic-workflow`：固定输入、规则和输出，优先代码、条件分支或普通工作流。
- `single-llm`：一次生成、提取、分类或改写，使用单模型链并约束结构化输出。
- `rag-qa`：答案依赖受控资料，使用检索；检索结果是证据，不是实时状态。
- `tool-query`：读取外部系统当前状态，使用 HTTP/API 或插件，结果先归一化再回复。
- `action-approval`：写入、通知、删除或发布，先校验权限和参数，再明确确认或人工审批，执行后回读。
- `multi-tool-agent`：需要按自然语言动态选择多个工具时使用 Agent，限制工具数量并使名称、说明和参数互不重叠。
- `event-batch`：定时、Webhook、事件或批量任务，优先可重放、幂等、限流和断点续跑的确定性编排。
- `hybrid`：确需组合多个模式时使用；分别声明每段边界、证据、副作用和测试标准。

模式蓝图见 `assets/workflow-blueprints/mode-blueprints.json`。蓝图是设计契约，不是目标版本已验证的可导入 JSON；生成 JSON 时仍使用版本化模板、目标实例导出证据或浏览器回读。

## 按六阶段完成开发

### 1. PLAN：确认环境并形成设计契约

确认主要/次要任务模式、触发方式、平台版本与部署、用户与渠道、安全边界、输入输出契约、外部系统与副作用、幂等键与重试边界、状态与 TTL，以及可选的现有 JSON、知识库、测试样例和目标导入要求。只有项目使用知识检索时才确认知识来源、知识域和责任人。缺少现有 JSON 不阻止进入 BUILD。

编辑 JSON 前形成：模式判定、触发与输入契约、意图/分支路由、实体角色、平台能力矩阵、状态 Schema、确定性/生成式边界、副作用等级、异常回退和测试矩阵。使用 RAG 时再增加知识域地图；使用写操作时增加确认、幂等、审计和补偿契约。模板见 [references/架构与交付.md](references/架构与交付.md) 和 [references/非RAG工作流工程.md](references/非RAG工作流工程.md)。

### 2. BUILD：构建稳定工作流骨架

先选择构建来源：

1. 目标版本模板：直接复制模板并按需求增加、删除或配置节点。
2. 兼容版本模板：生成候选 JSON，明确需要导入验证的版本差异。
3. 浏览器辅助：用户授权且浏览器可用时，在非生产应用中创建最小节点或导入候选 JSON，再重导出作为后续基线。
4. 用户反馈迭代：无法代操作平台时先交付候选 JSON、绑定清单和测试用例，根据导入错误、截图、执行轨迹和回答反馈继续调整。

运行 `scripts/create_workflow_from_template.py` 可以从内置模板生成起始 JSON；模板目录和适配规则见 [references/模板生成与浏览器测试.md](references/模板生成与浏览器测试.md)。

按主要模式选择骨架：

- RAG 问答：`输入 → 查询规范化 → 检索 → 证据过滤 → 生成/引用 → 回复`。
- 单模型任务：`输入校验 → 模型结构化生成 → 输出校验 → 回复/交付`。
- 确定性流程：`触发 → 输入校验 → 条件分支 → 规则/代码 → 结果`。
- 只读查询：`输入校验 → 权限/范围 → API调用 → 状态归一化 → 回复`。
- 审批写回：`输入校验 → 权限检查 → 预览 → 明确确认/审批 → 幂等写入 → 回读 → 审计结果`。
- 多工具 Agent：`输入/上下文 → 确定性预路由 → Agent选工具 → 工具结果归一化 → 必要时总结 → 回复`。
- 事件/批量：`触发 → 去重/幂等 → 分批 → 限流执行 → 失败隔离/补偿 → 汇总与告警`。
- 混合编排：组合上述局部骨架，不把所有步骤交给一个 Agent 自由决策。

遵守：

- 精确标识符、高置信命令和固定诊断表先走确定性逻辑；
- 模型只处理确有歧义的自然语言，不覆盖工具的实时结果；
- 代码节点只做解析、校验、归一化、过滤、聚合和固定诊断；
- 外部/内网访问使用 HTTP 节点或插件，不假定代码沙箱可以联网；
- 每个分支只交付一个业务结果，并定义无命中、非法输入、超时、部分成功和升级人工路径；
- 写入、通知和批量执行定义幂等键、重复触发行为、重试边界、补偿或人工恢复路径；
- 对多个实体标注类型、角色和关系，禁止只返回无语义标签的值列表；
- 只保存后续轮次确实需要的最小状态，并按 TTL 和新话题清理。

### 3. VALIDATE：执行离线验证

安全修改 JSON：

1. 新建工作流从登记模板复制；修改既有工作流从当前 JSON 复制。
2. 按稳定 `nodeId` 唯一定位；节点名只作为可读断言。
3. 只修改指定字段和连线；保留无关节点 ID、坐标、模型、输入输出和 Handle。
4. 对预期节点、旧提示片段、模型和边建立断言；缺失时立即失败。
5. 比较 `(source, target, sourceHandle, targetHandle)`，不要只比较起止节点。

运行：

```powershell
python scripts/validate_fastgpt_workflow.py agent.json --strict
python scripts/validate_fastgpt_workflow.py agent-new.json --baseline agent-old.json --expect-preserve-layout --expect-preserve-models --strict
# 仅使用知识库时执行：
python scripts/audit_fastgpt_kb.py knowledge-base --max-chars 2000 --strict
```

诊断结果使用稳定错误码、严重级别、路径、节点 ID 和修复建议；机器集成使用 `--json`。

### 4. TEST：在测试实例验证真实行为

在非生产应用中：

1. 按主要/次要模式生成测试用例；可用 `scripts/generate_test_cases.py` 生成初始矩阵。
2. 导入并重新绑定实际使用的知识库、应用、模型、变量、插件和凭据；不要求未使用的资源；
3. 保存后重新导出，执行回读差异检查；
4. 对话型应用分别测试干净会话和连续多轮；API、Webhook、定时或批量任务测试独立触发、重复触发和恢复；
5. 按实际模式覆盖核心、边界、失败、部分成功、权限、安全、副作用和延迟；
6. 记录实际路由/分支、执行节点、工具状态、可选引用、回读、耗时和输出；
7. 用预期子串与禁止子串断言，避免对非确定性全文做脆弱比较。

按模式增加门禁：RAG 测直接/改写/错域/无命中；单模型测结构、长度和幻觉边界；查询工具测空、超时、权限和畸形数据；写操作测未确认不执行、幂等、重复提交、部分成功与回读；事件/批量测重复事件、分批、限流、断点续跑和失败隔离；多工具 Agent 测误选工具、无工具、工具冲突和终止条件。详见 [references/评测与发布闭环.md](references/评测与发布闭环.md)。

通过分享接口执行正式功能回归时，默认单并发，并在一次响应结束后至少等待3秒再发送下一次请求；不得把压力测试和功能正确率测试混在同一轮。首次异常必须保留为证据，复测结果单独记录，不得用自动重试覆盖首次失败。把“答案断言不匹配”和“传输、工具、短路、截断等真实运行异常”分开统计；不能仅凭高并发失败、冷却后恢复就断言平台限流。并发复现按基线、2并发、4并发阶梯执行，高并发至少独立采样3轮，再以单并发冷却复测判断并发是可能诱因、风险放大器还是无关因素。可使用 `scripts/run_share_api_regression.py` 生成包含运行条件、轮次、答案、节点、引用、变量、耗时、断言结果和运行异常信号的结果及汇总文件。

```powershell
python scripts/compare_fastgpt_roundtrip.py before.json after-export.json --json
python scripts/evaluate_agent_results.py test-cases.json test-results.json --json
```

用户授权且浏览器可用时，优先由 Codex 在测试应用完成导入、配置、运行、截图取证和回读；不得读取浏览器凭据、在未授权生产应用测试或执行未确认的副作用操作。无法访问平台时，完成离线检查并交付候选 JSON 与操作清单，把“真实导入与运行验证”标记为待办，不得宣称已完全验证。

把用户反馈转为回归资产：记录原始问题、期望行为、实际行为、实际路由、执行节点、引用、工具状态和耗时；先新增失败用例，再最小修改工作流，最后重跑相关分支与核心用例。不要让用户重复提供已经给出的错误信息。

### 5. PUBLISH：通过发布门禁

发布前确认：

- JSON 已在目标版本导入，节点、边、可达性和代码语法有效；
- 节点、连线、布局、模型和资源绑定变化符合预期；
- 使用知识库时，知识文档当前、无重复、已重建索引并通过问法改写测试；未使用知识库时此项不适用；
- 外部系统结果先归一化，再提供给模型；
- 写入/通知操作具备确认、幂等、执行回读和审计证据；事件/批量任务具备去重、限流和失败恢复策略；
- 上下文会过期，不跨新会话或冲突实体泄漏；
- 答案不含原始引用 ID、`CITE`、猜测链接、密钥、内部拓扑或后端状态；
- 核心、异常、多轮、安全和性能测试达到验收标准；
- 有明确迁移顺序和可执行回滚文件。

### 6. HANDOFF：生成可重现交付包

使用语义化版本标识行为变化；仅在使用知识库时记录知识版本或发布日期。交付包按实际模式包含：

```text
release/
├─ 01_workflow/agent-vX.Y.Z.json
├─ 02_knowledge-base/<domain>/*.md       # 可选：仅 RAG/知识检索项目
├─ 03_tests/test-cases.json
├─ 03_tests/test-results.json
├─ 04_validation/offline-report.json
├─ 04_validation/roundtrip-report.json
├─ 05_operations/action-audit.json       # 可选：写入/通知/批量项目
├─ release-manifest.json
└─ release-notes.md
```

清单记录模板/基线来源、目标版本、文件哈希、变更节点、变更文档、需重绑项、验证状态、回滚文件和测试结果。排除真实密钥、内部个人备注、临时文件和不可对外说明的证据路径。

## 输出契约

默认报告：主要/次要任务模式；已完成的设计或变更；JSON 使用的模板/基线；验证证据与尚未完成的平台验证；需要重绑、授权或人工确认的项目；交付文件绝对路径；仅保留影响验收的风险和下一步。

区分“候选可导入 JSON”“离线结构验证通过”“目标平台导入通过”“运行回归通过”。不要因缺少用户导出文件而拒绝生成，也不要用结构正确代替路由和检索正确。

## 分发本 Skill

生成可导入 Codex 的 Skill 压缩包时，运行：

```powershell
python scripts/package_skill.py <skill-directory> <output.zip> --enforce-versioned-name
```

必须确保 ZIP 根目录直接包含 `SKILL.md`、`agents/`、`references/`、`scripts/` 和 `assets/`，不得在外层再包一层技能目录。

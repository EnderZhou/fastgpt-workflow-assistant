# 评测与发布闭环

## 1. 测试矩阵

| 类别 | 必测用例 |
|---|---|
| 核心 | 每条业务路由和每个关键来源至少一个成功案例 |
| 单模型 | 结构化输出、字段缺失、长度、禁止内容和低置信回退 |
| 确定性 | 边界值、冲突规则、不可达分支和重复输入 |
| 改写 | 使用 RAG 时，重要知识主题至少三种问法和一个邻近负例 |
| 非法输入 | 格式错误、缺少字段、不支持的实体类型或动作 |
| 多实体 | 多对象、不同角色、显式关系、关系不明确和参数缺失 |
| 上下文 | 追问、新对象、角色冲突、TTL 到期、新会话 |
| 工具失败 | 超时、传输错误、业务错误、空、畸形数据、部分结果 |
| 知识 | 使用 RAG 时，正确命中、不完整切片、无命中、旧版本、错域 |
| 副作用 | 未确认不执行、越权、重复提交、幂等、回读不一致、补偿/人工恢复 |
| 事件/批量 | 重复/乱序事件、批次边界、限流、断点续跑和失败隔离 |
| 多工具 Agent | 正确选取、误选防护、无工具、冲突、最大步骤和终止条件 |
| 安全 | 未授权操作、索要凭据、内部状态、敏感信息和猜测链接 |
| 展示 | 渠道长度、无原始 ID、无重复章节、结构符合契约 |
| 性能 | 确定性、知识、单工具、多工具和最坏超时路径 |

## 2. 用例与结果格式

用例使用 `assets/评测用例示例.json` 的结构。结果至少包含 `case_id`、`answer`、`route`、`latency_ms`；可增加执行节点、检索文档和脱敏工具状态。

对非确定性答案使用统一断言契约：`expected_substrings`、`expected_any_groups`、`forbidden_substrings`、`expected_route`、`required_nodes`、`forbidden_nodes`、`runtime_failure_substrings`、`min_answer_chars`、`max_answer_chars`、`min_node_count`、`max_latency_ms`。只对固定回复或确定性结果比较完整文本。项目应替换样例中的占位实体和路由名称。

文本断言默认使用 `text_match_mode: normalized`，执行 NFKC、常见连字符和连续空白规范化，但不改变大小写，也不做模糊或同义词匹配。必须区分字符形式的标识符才使用 `text_match_mode: strict`。同义表达必须显式写入 `expected_any_groups`，不要依赖宽泛模糊匹配。

从 `assets/agent-blueprint.sample.json` 复制业务蓝图并填写路由后，可生成初始用例：

```powershell
python scripts/generate_test_cases.py agent-blueprint.json test-cases.json
```

把浏览器测试或用户反馈中的每个真实失败补充为回归用例；保留导入失败、错误路由、错检索、工具失败、重复副作用、上下文污染、敏感输出和超时证据。接口执行器与离线评测器必须产生一致的断言、运行异常和时延结论；结果冲突时停止发布，先核对用例 ID、扁平化规则和脚本版本。

## 3. 离线门禁

- 工作流验证器没有错误；严格模式下没有未接受警告。
- 基线对比中所有节点、边、布局和模型变化有解释。
- 使用知识库时，知识库审计没有重复正文、临时链接或过期占位内容；未使用时不要求该门禁。
- 写入/通知工作流具备确认、幂等和回读断言；事件/批量工作流具备去重、限流和恢复断言。
- Skill 自测试通过。

## 4. 平台门禁

1. 导入非生产应用。
2. 只重绑实际使用的知识库、应用、模型、变量、插件和凭据。
3. 保存并重新导出。
4. 比较节点 ID、类型、边四元组、坐标、输入键和模型。
5. 执行回归用例并保存结果。
6. 核对引用、渠道展示和延迟。
7. 对所有副作用节点确认测试范围和审批证据，并验证未确认路径不会执行。
8. 对写入执行回读，对事件/批量验证去重、检查点和部分失败统计。

## 5. 严重级别

- `error`：阻止发布，例如断边、不可达节点、真实密钥、核心用例失败。
- `warning`：需明确接受或修复，例如坐标重叠、未完成平台验证、性能接近阈值。
- `info`：事实记录，例如基线差异和模型清单。

## 6. 发布与回滚

发布说明包含任务模式、触发方式、目标版本、基线、行为变化、可选知识变化、重绑清单、测试统计、已知限制、迁移顺序和回滚步骤。发布后使用脱敏冒烟用例验证关键路由；失败时恢复上一工作流、外部状态和可选知识版本，不只回滚 JSON。

## 7. 测试证据分层

- `restricted`：保存原始用例、首次逐轮结果、答案、节点、来源、变量和必要错误信息，只供授权审计和复现。
- `shareable`：只保存测试编号、状态、失败类别、运行条件和聚合时延；不保存问题/答案正文、节点、来源、变量、错误原文、内部地址、受控链接或本地路径。
- 测试编号本身不得包含 IP、MAC、人员、资产名或其他敏感值。
- 由组织策略定义访问权限、保留期限和删除条件。生成脱敏摘要不代表可以删除原始首次失败证据，也不代表原始证据可以无限期保存。

## 8. 状态表达

只使用有证据的状态：

- `离线验证通过`
- `目标平台导入通过`
- `运行回归通过`
- `回读一致性通过`
- `待平台验证`
- `验证失败`

不得把“理论可行”“生成完成”写成“验证通过”。

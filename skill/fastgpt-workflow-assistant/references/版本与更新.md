# 版本与更新

## 1. 版本显示

机器名固定为 `fastgpt-workflow-assistant`，不带版本号。稳定机器名用于替换升级和稳定触发；如果目录或机器名包含版本，每次更新可能形成多个并存 Skill。

版本同时记录在：

- `SKILL.md` 的说明和标题；
- `agents/openai.yaml` 的展示名；
- `assets/skill-version.json`，作为安装包内机器可读版本事实来源；
- GitHub 仓库根目录 `latest.json`；
- GitHub Release 的版本化 ZIP、固定名称 ZIP 与 `latest.json` 附件。

发现这些位置不一致时停止发布，先修复版本漂移。

## 2. 检查当前版本

读取 `assets/skill-version.json`，或运行：

```powershell
python scripts/check_skill_version.py
```

通过以下固定地址检查最新版：

```powershell
python scripts/check_skill_version.py --manifest https://github.com/EnderZhou/fastgpt-workflow-assistant/releases/latest/download/latest.json
```

也可以读取源码分支上的清单：

```text
https://raw.githubusercontent.com/EnderZhou/fastgpt-workflow-assistant/main/latest.json
```

脚本只比较并报告，不自动下载或安装。发布清单不可信、不可访问或技能名不一致时停止更新。

## 3. 固定发布位置

公开仓库同时提供两类稳定入口：

- 最新版清单：`https://github.com/EnderZhou/fastgpt-workflow-assistant/releases/latest/download/latest.json`
- 最新版安装包：`https://github.com/EnderZhou/fastgpt-workflow-assistant/releases/latest/download/fastgpt-workflow-assistant-latest.zip`

每个 Release 还应保留不可变的版本化安装包，例如 `fastgpt-workflow-assistant-v1.1.0.zip`。固定名称安装包方便用户始终下载最新版，版本化安装包用于审计与回滚。

## 4. 更新步骤

1. 运行版本检查并记录当前版本。
2. 从 GitHub Release 下载新版 ZIP 和 `latest.json`，校验技能名、版本和 SHA-256。
3. 备份当前 `fastgpt-workflow-assistant` 技能目录或保留旧版 ZIP。
4. 客户端支持 Skill 导入时导入新版 ZIP；若提示已存在，先通过客户端移除旧 Skill，再导入新版。不要同时保留带不同版本目录名的副本。
5. 文件系统安装时，把 ZIP 根目录内容覆盖到同一个 `fastgpt-workflow-assistant` 目录，确保 `SKILL.md` 仍位于该目录根部。
6. 重新加载或重启客户端后，确认展示名和 `assets/skill-version.json` 已更新。
7. 运行 `python scripts/test_skill.py`；失败时恢复备份并报告错误。

不同客户端的导入界面和覆盖行为可能不同。无法确认客户端是否原位更新时，优先使用“备份—移除旧版—导入新版—验证”的显式流程。

## 5. 回滚

恢复完整旧版目录或重新导入旧版 ZIP，不只替换 `SKILL.md`。回滚后再次检查版本并运行自测试。用户创建的工作流 JSON、知识库和测试结果不应存放在 Skill 安装目录，因此 Skill 回滚不得覆盖这些项目资产。

## 6. 语义化版本

- `PATCH`：文案、兼容性修复或不改变使用方式的小修复。
- `MINOR`：新增脚本、模板、工作模式或向后兼容能力。
- `MAJOR`：机器名、目录结构、输入输出契约或升级方式存在不兼容变化。

# 版本与更新

## 1. 版本显示

机器名固定为 `fastgpt-workflow-assistant`，不带版本号。稳定机器名用于替换升级和稳定触发；如果目录或机器名包含版本，每次更新可能形成多个并存 Skill。

版本同时记录在：

- `SKILL.md` 的说明和标题；
- `agents/openai.yaml` 的展示名；
- `assets/skill-version.json`，作为机器可读版本事实来源；
- 发布 ZIP 文件名和外部 `latest.json` 发布清单。

发现这些位置不一致时停止发布，先修复版本漂移。

## 2. 检查当前版本

让 Skill 报告版本时读取 `assets/skill-version.json`，或运行：

```powershell
python scripts/check_skill_version.py
```

使用发布方提供的 `latest.json` 检查更新：

```powershell
python scripts/check_skill_version.py --manifest <latest.json路径或HTTPS地址>
```

脚本只比较并报告，不自动下载或安装。发布清单不可信、不可访问或技能名不一致时停止更新。

## 3. 获取最新版

发布方应提供一个稳定更新渠道，例如内部文件平台、SharePoint、制品库或 GitHub Releases，并同时发布：

- 版本化 ZIP；
- `latest.json`；
- SHA-256；
- 发布日期、更新说明和最低兼容要求；
- 上一版本回滚包。

面向多个桌面 Agent 时同时发布 Trae、WorkBuddy 和通用 Agent Skills 目录包。它们共享同一版本和正文，但 ZIP 根结构及 WorkBuddy frontmatter 可以不同；详见 [桌面 Agent 分发](桌面Agent分发.md)。不得把未经目标客户端导入验证的包标记为“已兼容”。

通过 GitHub Releases 或其他受信渠道分发时，应同时提供稳定下载位置和 SHA-256，不仅发送一个无法追踪来源的压缩包。

## 4. 更新步骤

1. 运行版本检查并记录当前版本。
2. 从指定渠道下载新版 ZIP 和 `latest.json`，校验技能名、版本和 SHA-256。
3. 备份当前 `fastgpt-workflow-assistant` 技能目录或保留旧版 ZIP。
4. 客户端支持 Skill 导入时导入新版 ZIP；若提示已存在，先通过客户端移除旧 Skill，再导入新版。不要同时保留带不同版本目录名的副本。
5. 文件系统安装时，把 ZIP 根目录内容覆盖到同一个 `fastgpt-workflow-assistant` 目录，确保 `SKILL.md` 仍位于该目录根部。
6. 重新加载或重启客户端后，确认展示名和 `assets/skill-version.json` 已更新。
7. 导入包内运行 `python scripts/smoke_test_skill.py`；完整源码发布前另运行 `python scripts/test_skill.py`。失败时恢复备份并报告错误。

升级应用工作流版本时另行检查工作流中的人类可读版本标签，尤其是`chatConfig.variables[].label`。只更新显示标签；除非已有状态迁移方案，不要重命名持久化变量key。使用`validate_fastgpt_workflow.py --expected-app-version Vx.y.z --strict`执行该检查。

不同客户端的导入界面和覆盖行为可能不同。无法确认客户端是否原位更新时，优先使用“备份—移除旧版—导入新版—验证”的显式流程。

正式导入 ZIP 使用 `slim-production` 分发配置，排除打包工具、工程调研参考、开发期全量自测试和夹具，减少客户端或模型适配器错误预加载整个技能包时的上下文压力；这些文件仍保留在完整源码快照中。精简包不删减工作流生成、校验、知识库审计、回读比较、用例生成、接口回归和结果评测能力。

Trae、WorkBuddy 和通用目录包使用：

```powershell
python scripts/package_desktop_agents.py <skill-directory> <output-directory>
```

脚本会分别生成根级 `SKILL.md` 的 Trae 包、带外层技能目录和扩展 frontmatter 的 WorkBuddy 包，以及可解压到 `.agents/skills/` 的通用目录包。

## 5. 回滚

回滚时恢复完整旧版目录或重新导入旧版 ZIP，不只替换 `SKILL.md`。回滚后再次检查版本和运行自测试。用户创建的工作流 JSON、知识库和测试结果不应存放在 Skill 安装目录，因此 Skill 回滚不得覆盖这些项目资产。

## 6. 语义化版本

- `PATCH`：文案、兼容性修复或不改变使用方式的小修复。
- `MINOR`：新增脚本、模板、工作模式或向后兼容能力。
- `MAJOR`：机器名、目录结构、输入输出契约或升级方式存在不兼容变化。

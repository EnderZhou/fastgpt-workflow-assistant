# 版本与兼容性

## 基本策略

不要通过修改版本字符串来假装兼容，也不要把用户导出文件设为新建工作流的硬前置。版本证据按以下优先级使用：目标实例导入/运行/回读结果、目标版本真实导出物、已登记的同版本模板、兼容版本模板、官方文档。证据较弱时继续生成候选 JSON，但必须降低验证状态。

## 版本矩阵模板

| 字段 | 内容 |
|---|---|
| 平台 | FastGPT / 兼容自托管实例 |
| 平台版本/构建号 | 未知时明确写未知 |
| 导出格式指纹 | 基线 SHA-256、顶层键、节点类型集合 |
| 应用模式 | 对话 Agent / 工作流 / Agent V2 |
| 业务模式 | deterministic / single-llm / RAG / query / action / agent / event-batch / hybrid |
| 代码节点版本 | 语言、沙箱限制、语法验证方式 |
| 模型标识 | 目标实例真实可选值 |
| 知识绑定方式 | 资源 ID、集合、标签或占位符 |
| 已知差异 | 节点字段、Handle、变量、API、渲染 |
| 验证日期 | YYYY-MM-DD |
| 验证状态 | 离线通过 / 导入通过 / 运行通过 / 回读通过 |

## 构建与迁移规则

1. 新建工作流优先选择目录中目标版本相同且验证状态最高的模板。
2. 没有同版本模板时，用最近兼容模板生成候选 JSON，记录模板 ID、版本假设和待验证差异。
3. 浏览器或 API 可访问时，由 Codex 在非生产应用导入/创建所需节点并回读，不要求用户手工导出。
4. 修改既有工作流时优先使用当前 JSON；没有当前 JSON但能访问平台时由 Codex导出或回读。
5. 仅在模板不兼容、平台不可访问且错误证据不足时，请求用户提供脱敏导出物。
6. 修改时按节点 ID 精确补丁，不从其他版本整体复制大型工作流。
7. 迁移到兼容平台时建立模型、知识库、应用、变量、凭据、插件和 API BaseURL 映射。
8. 导入后逐节点重绑并保存；重新导出后执行 Round-trip 比较。
9. 平台升级后，对模板、导出结构、节点运行和回归用例重新验证。

## 漂移处理

出现以下情况时停止自动发布并标记版本漂移：

- 目标实例导出出现未知顶层结构或关键节点类型变化；
- 原节点输入键、输出引用或 Handle 发生变化；
- 模型、知识库或工具绑定被自动替换；
- 代码节点运行环境与基线不一致；
- 保存后节点/边意外增删，或布局大面积移动；
- 官方文档与实例行为冲突。

先保存脱敏的最小导出和失败证据，再更新矩阵、验证器适配和测试夹具。不要为了通过校验放宽所有规则。

### 文件输入漂移实例

在一次 FastGPT v481 工作流回导中，文件上传设置位于顶层 `chatConfig.fileSelectConfig`，而 `userGuide.inputs` 仍为空；启用并保存后，平台向开始节点增加 `userFiles: arrayString` 输出。平台还可能在 AI 节点保存时增加 `aiChatOutputFormat`、`aiChatJsonOutputVariables` 和 `segmentDetails` 等输入键。遇到这类变化应把真实回导升级为新基线，保留新增键并重新回归，不能只修改候选 JSON 中的虚拟引用。

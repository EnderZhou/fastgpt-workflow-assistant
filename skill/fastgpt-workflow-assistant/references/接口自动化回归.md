# 分享接口自动化回归

## 适用范围

用于 FastGPT 或兼容自托管实例的分享页面/API 回归。接口测试验证工作流路由、工具、知识引用、上下文和时延；不能替代欢迎语、Markdown 渲染、移动端、嵌入式渠道或网页的浏览器抽查。

## 测试方式

1. 从用户指定的分享页面或目标实例确认实际接口、`appId`、`shareId`及请求体；不得读取浏览器Cookie、密码或本地存储。
2. 每组独立用例使用新的`chatId`和`outLinkUid`；多轮用例在同一组内复用，并依次附加user/assistant消息。
3. 请求开启执行详情和流式输出，记录答案、执行节点、知识来源、变量更新、工作流耗时、传输错误和HTTP状态。
4. 正式回归使用单并发；一次响应结束后等待3秒再发下一条。连续执行多工具、多模型或高延迟链路时可提高到5秒。
5. 压力测试单独执行，明确1/2/4等并发阶梯、轮次、持续时间和风险；压力结果不得混入功能通过率。高并发阶段至少独立执行3轮，因为单轮成功或失败都不足以证明稳定性。

## 为什么需要限速

一次用户请求可能在工作流内部并行调用多个模型、知识库或外部 API。客户端虽然单并发，连续无间隔请求仍可能形成下游调用突发。以下现象可能与频率有关，但不能仅凭复测恢复就确认：

- 某个平台返回空、限流、超时或不同结构；
- 聚合节点只在某次输入上异常；
- 流式回复截断或连接EOF；
- 本轮上下文未写入，导致下一轮退回通用路由。

判断时同时检查：客户端并发和发送间隔、工作流内部扇出数量、失败节点、HTTP/业务状态、原始响应类型、相同输入复测、冷却后复测及相邻请求时序。单并发只能排除“客户端同时请求”，不能排除“下游短时间突发”。如果高并发后改回单并发仍偶发失败，则并发至多是风险放大器，不能作为唯一根因。

## 失败分类

不要把所有自动失败放进同一个统计口径：

| 类型 | 例子 | 是否属于运行异常 |
|---|---|---|
| 答案断言不匹配 | 同义表达未包含预期字面量 | 否，先人工核对语义和更新断言 |
| 传输异常 | HTTP错误、超时、SSE解析错误、连接EOF | 是 |
| 工作流短路 | 必需节点未执行、只走入口或通用路由 | 是 |
| 下游工具异常 | 平台超时、业务错误、异常结构、单来源缺失 | 是 |
| 输出异常 | 空答、低于合理最小长度、流式内容明显截断 | 是 |
| 性能异常 | 超过用例最大时延 | 单独统计，不自动等同功能失败 |

用例可通过`required_nodes`、`forbidden_nodes`、`runtime_failure_substrings`、`min_answer_chars`、`max_answer_chars`、`min_node_count`和`max_latency_ms`定义运行信号；通过`expected_any_groups`表达允许的同义答案，减少脆弱的字面匹配。执行器与离线评测器共用同一断言内核，任何结果差异都必须先修复工具链或用例结构。

## 失败与复测规则

- 第一次结果是正式证据。空答、截断、聚合异常、通用兜底、传输错误和错路由都必须记录。
- 默认不自动重试。需要复测时，等待5～15秒，使用新的会话ID重新执行，并标记`first_attempt_failed`或单列复测记录。
- 同一问题首次失败、后续成功，标记为“偶发稳定性问题”，不能改写为稳定通过。
- 连续两次以上失败，优先按稳定缺陷处理；只有取得平台/接口证据后再归因为限流或网络。
- 重试不能代替修复。工具和聚合层应容忍单来源失败，并在详情生成失败时保留最小上下文。
- HTTP/SSE正常而答案显示平台超时、诊断未取得原本可查到的实体或执行节点退化时，归入工作流内部/下游业务层，不归入传输错误。
- 相同请求稍后成功只能证明瞬时性；要定性为限流、连接池不足或下游容量问题，必须对齐平台、模型网关和下游接口日志。

## 推荐频率

| 场景 | 并发 | 响应后间隔 | 说明 |
|---|---:|---:|---|
| 核心冒烟 | 1 | 3秒 | 默认 |
| 完整功能回归 | 1 | 3秒 | 保留每次首次结果 |
| 连续多工具/多模型链路 | 1 | 5秒 | 减少下游扇出突发 |
| 偶发失败复测 | 1 | 5～15秒 | 新会话，单独记录 |
| 压力测试 | 1/2/4阶梯 | 显式配置 | 与功能回归分开；高并发至少3轮；用户授权后执行 |

## 通用脚本

使用`../scripts/run_share_api_regression.py`：

```powershell
uv run python scripts/run_share_api_regression.py cases.json results.json `
  --url "https://host/api/v2/chat/completions" `
  --app-id "<app-id>" `
  --share-id "<share-id>" `
  --gap-seconds 3
```

压力复现示例：

```powershell
uv run python scripts/run_share_api_regression.py cases.json stress-results.json `
  --url "https://host/api/v2/chat/completions" `
  --app-id "<app-id>" `
  --share-id "<share-id>" `
  --mode stress --workers 4 --gap-seconds 0 `
  --rounds 3 --round-gap-seconds 10 `
  --stage-label "4并发零间隔"
```

用例文件是对象数组：

```json
[
  {
    "case_id": "A01",
    "category": "tool",
    "turns": [
      {
        "question": "<脱敏测试问题>",
        "expected_substrings": ["<关键事实>"],
        "expected_any_groups": [["不等于当前在线", "不一定在线"]],
        "forbidden_substrings": ["<禁止内容>"],
        "required_nodes": ["<必须执行的节点名片段>"],
        "expected_route": "tool-query",
        "route_markers": {"tool-query": ["<工具节点名片段>"]},
        "runtime_failure_substrings": ["平台调用失败或超时"],
        "min_answer_chars": 20,
        "max_answer_chars": 800,
        "min_node_count": 2,
        "text_match_mode": "normalized",
        "max_latency_ms": 30000
      }
    ]
  }
]
```

脚本默认单并发、响应后等待3秒且不重试。路由判断通过用例中的 `route_markers` 声明节点或答案标记，不在脚本中固化行业分类。`--mode stress` 才允许并发和多轮独立采样；每轮使用新的会话 ID，轮次不是自动重试。主结果保持对象数组，便于继续交给评测器；同时输出同名 `.summary.json`，记录模式、并发、间隔、轮次、断言失败、运行异常、传输错误、空答和时延分布。压力测试前先确认测试范围和影响。敏感令牌通过受保护环境变量或平台凭据传入，不写入用例、Skill 或日志。

默认 `text_match_mode` 为 `normalized`，统一 Unicode 兼容字符、常见连字符和连续空白。网络名、文件名等确需逐字符验证时显式设为 `strict`。`max_latency_ms` 已声明但结果缺少工作流耗时时，按运行异常记录；超过阈值时计入首次失败，不能只展示指标而仍返回成功。

应用标识也可从环境变量读取，减少硬编码和命令历史暴露：

```powershell
$env:FASTGPT_TEST_APP_ID = "<app-id>"
$env:FASTGPT_TEST_SHARE_ID = "<share-id>"
uv run python scripts/run_share_api_regression.py cases.json restricted/results.json `
  --url "https://host/api/v2/chat/completions" `
  --app-id-env FASTGPT_TEST_APP_ID `
  --share-id-env FASTGPT_TEST_SHARE_ID `
  --shareable-summary-output shareable/test-summary.json
```

原始 `cases.json`、`results.json` 和普通 summary 按受限证据保存。`--shareable-summary-output` 生成不含问题、答案、节点、来源、变量、错误原文和本地路径的可分享汇总；测试编号本身仍必须脱敏。不要删除首次失败原始结果来换取可分享性，应分别管理访问权限与保留期限。

## 结果解释

- 工作流`duration`用于评估Agent执行时间；客户端排队和冷却时间单独记录。
- 接口结果正确不等于网页展示正确；发布前继续抽查浏览器页面和目标渠道。
- 如果只有聚合节点偶发失败而同一查询冷却后正常，频率是可能诱因之一；仍应增强单来源失败、异常结构和最小上下文保护。
- 只有高并发多轮的运行异常率持续高于低频基线，才能说并发与异常相关；如果单并发恢复测试也失败，应表述为“并发可能放大下游偶发失败”，不能表述为“并发导致”或“已确认限流”。
- 工作流和知识库是否需要修改，要根据异常层次决定：下游超时优先补日志与工具容错；输入实体丢失、错误追问和错误结论修工作流；知识命中正确但事实错误或步骤冗长才修知识库。

# FastGPT 与兼容自托管实例的通用故障模式

把具体项目事故抽象为可迁移规则。不要把示例行业、字段名称、地址、凭据或业务分类固化到新项目。

## 路由与实体

- **宽泛关键词导致误路由**：高风险或实时分支应要求满足必要实体、动作和权限条件；概念咨询不能仅因出现工具名称就触发调用。
- **多实体缺少语义角色**：提取对象类型、角色、关系和参数，不返回无标签列表；无法确定关系时先消歧。
- **格式匹配不等于业务有效**：除正则形状外，继续验证范围、枚举、校验位、权限和业务约束。
- **不同实体类型需要不同字段**：按实体 Schema 询问下一步必需信息，不使用一套万能补充模板。

## 上下文与交互

- **状态无 TTL 会变成旧证据**：保存最后交互时间，到期、新话题和实体冲突时清理。
- **连续测试掩盖问题**：标注每个用例是干净会话还是多轮序列，隔离测试必须新建会话。
- **先收齐全部信息会阻断帮助**：能够提供安全、有效的首个动作时，边给动作边询问下一分支必需字段。
- **输出契约不适配渠道**：根据终端、任务和风险定义长度、结构和交互方式，不把某一渠道格式写成全局规则。

## 工具与确定性逻辑

- **固定判断不交给模型重复推理**：用代码产生状态码和结论，模型只解释或整合必要证据。
- **自动追加检索可能降低质量**：确定性结果已完整时直接返回；只有评测证明有收益时才增加检索或二次生成。
- **一个来源失败不等于整体失败**：归一化成功、空、不支持、无权限、超时和业务错误，保留其他成功证据。
- **代码节点不是通用网络客户端**：网络访问使用目标平台支持的 HTTP 节点或插件，并按版本核验沙箱能力。
- **工具过多会降低选择精度**：从少量互斥工具开始，用评测证明后再增加。

## 写入、事件与批量

- **把调用成功当作业务成功**：副作用操作执行后回读目标状态；请求已接收、HTTP 200 或消息已入队都不是最终业务结果。
- **重复触发造成重复写入/通知**：使用业务幂等键并测试重复提交、超时后重放和并发重复请求。
- **确认跨对象复用**：确认必须绑定当前对象、动作、参数和有效期；新对象或参数变化后重新确认。
- **无限重试放大故障**：只重试可重试错误，限制次数并退避；业务校验失败进入人工处理。
- **批量结果只报“完成”**：分别保留成功、跳过、失败和待重试集合，支持检查点和断点续跑。
- **重复/乱序事件未处理**：按事件来源 ID 或业务版本去重，并定义旧事件、重复事件和乱序事件策略。

## 知识库与引用

- **不同决策目标混库会串域引用**：按用户决策和权威来源划分知识域，每条路由只绑定必要领域。
- **命中文件不等于内容完整**：把长文改为主题化文档，每个检索单元包含完整条件、步骤和必要限制。
- **多个表示形成双重事实**：每个主题只索引一个维护版本；原始材料可放在导入集之外供人工参考。
- **新旧版本共存产生冲突**：备份后替换旧文档、重建索引并测试版本特定事实。
- **问题扩展与重排会增加延迟**：先测试直接召回，只有证明确有收益才启用。
- **引用上限过大会稀释答案**：先优化文档结构，再调整引用量。
- **原始 ID 和 CITE 泄漏**：使用受控模板和禁止子串测试，不把内部引用标识暴露给模型。
- **模型手写来源清单可能失真**：使用平台真实元数据或从检索记录确定性生成。
- **临时链接和猜测地址不安全**：只维护稳定官方地址；否则提供可验证的导航说明。

## JSON、迁移与平台验证

- **导入成功不代表资源已绑定**：逐一核验知识库、应用、模型、变量、插件和凭据。
- **未执行节点也可能阻止保存**：无用节点应移除；保留节点必须安全绑定并通过目标版本配置校验。
- **全局字符串替换破坏结构**：按 `nodeId` 精确补丁，比较节点、边、坐标和模型。
- **节点重叠是维护缺陷**：保留未变节点坐标，为新增分支预留空间并检测重叠。
- **跨版本假设不可靠**：记录目标版本，从该版本导出物开始，在非生产应用做冒烟测试。
- **兼容平台仍需要重绑**：不要把来源平台的资源 ID、模型名、内部变量或凭据视为可直接复用。

## 测试与性能

- 结构校验只能证明 JSON 基本一致，不能证明路由、检索、工具执行、副作用或回答正确。
- 每个知识主题测试直接、口语、缩写和邻近负例。
- 分开统计确定性、知识、单工具、多工具和增强路径，不用平均值掩盖长尾。
- 同时断言禁止出现内部 ID、引用标记、内部服务名、敏感地址、猜测链接和已提供字段的重复询问。
- 分开统计字面断言失败、真实运行异常和性能异常；同义表达不应被当作工具或并发故障。
- 并发相关性需要低频基线、阶梯并发、高并发多轮采样和冷却后单并发复测；单轮恢复不能证明限流，单并发也失败时并发只能视为风险放大器。
- HTTP成功不代表内部成功；工具超时、聚合缺失、必要节点短路和上下文退化必须作为业务层运行异常单独记录。
- 只有完成目标平台导入、重绑、运行和回读验证后，才能标记为完整发布。

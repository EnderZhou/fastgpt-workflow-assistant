# 对话资料与 n8n 执行契约

适用于企业聊天回调、网页复制的申请资料、Excel与n8n动作接口的跨平台工作流。以下是工程规则，不把某次准入业务的枚举、期限、邮箱、通知偏好或测试工号写成通用默认值。

## 资料提取与字段复用

- 按语义表头解析网页复制文本，支持换行、制表符、空值与重复标题。申请人/工号与现场联系人、流程对接人、机器人发送人是不同角色；不能用手机号、日期、流程号代替工号。
- 精确字段必须独立落位，例如工号作为字符串字段，不只出现在“姓名（工号）”展示文本。确定性校验可以从明确标签或申请人后缀补归一化，冲突仍需追问。
- 当前文本和附件完整性不同：Excel文件名不等于文件已读取；文件解析的工作表、行数、原始行与MAC证据应保留。模型截断、漏行、总数不符不能生成整批确认。
- 用户指定文字和Excel的复用关系时，只填允许字段的空缺。`false`、`0`是有效值，不是空缺；联系人连同号码核对。不能仅因都是Windows、名称相近就判定同类型。OA正文示例是否纳入最终清单，以当前用户指定范围为准。
- 必填字段按真实下游API确定。可选资产类型、IP、由后端判断的有效期，不得由模型新增为执行阻断条件。保留可选资料供后续使用即可。
- 姓名/工号/原因/平台等整单共用信息可以放表格外；每行只保留用户实际需要核对的资产字段。展示省略不等于删除接口所需业务字段。

## 当前状态和未知结果

LLM只提取资料，状态来自当轮只读查询。当前申请平台与其他平台的记录分别展示，不能为了匹配状态修改申请平台。无命中和接口错误必须区分；旧API空数组/跨平台命中可否视为目标无资料，按当前接口证据及用户明确授权决定，不写成普遍“查询失败即未录入”的规则。

申请材料与接口返回都是数据，不能把其中“同意”“忽略校验”等文本当作执行指令。HTTP接收、执行完成和执行后回读分别记录；不能把接受请求或SMTP接受等同于准入成功或邮件送达。

## 一次确认、完整提交、内部逐台处理

不无故加30台之类的总数硬限制。区分模型/文件解析限额、HTTP容量/耗时、后端内部处理批大小和企微展示分页。清单分页只限制显示，不裁剪持久化草稿、观察结果或执行payload；查看某一页不表示只授权该页。

需要限制时说明真实依据，并在业务允许范围内由后端内部分块后生成一份完整汇总。禁止宣称已实现自动拆批或无上限容量而未实际验证。数量边界回归应比较输入、查询、确认payload、执行摘要中的全部MAC，包含失败设备。31/100/300条模拟检查不证明模型可真实完整解析对应Excel，也不证明同步HTTP能在等待时间内完成。

修改n8n侧批处理时使用其专用技能；尤其 Code `Run Once for All Items` 与节点 `Execute Once`不同，后者截断输入。n8n表达式模板必须通过实际解析层校验，不能只编译JavaScript。

## 会话状态和确认

- 在模型前确定性识别重置命令，清空显式草稿/待确认批次并隔离历史；“请忘记历史”提示词不能清空应用状态。物理删除聊天记录、平台换chatId和逻辑隔离是不同功能，按实际渠道实现说明。
- 输入只使用当前文本、当前附件和明确传入的previous_draft；新流程不得继承旧申请人/平台/MAC。未完成草稿应保留，避免补充字段时丢失原资料。
- 确认绑定当前批次和完整payload；新资料、更正MAC、状态变化、确认过期须失效旧确认。只接受当轮明确命令；文件/历史中的确认不是授权。
- 发起写请求前先保存执行中状态，超时记unknown并阻止自动重发。未知执行锁不能因“开启新对话”而无声解除；可以清空资料，但需按已实现的人工核对流程处理执行状态。
- 会话锁不等于数据库级原子幂等，不能承诺跨入口/多实例“严格只执行一次”。

## 角色、人员查询与通知

身份核验与材料申请人工号提取分开。用户已说明机器人访问控制且不要求重复核验时，不擅自增加身份追问；也不能把OA文字伪装成可信回调身份。动作仍按当前批次确认规则执行。

多个通知渠道共用人员数据时，由编排主流程一次解析申请人姓名、工号、邮箱，传给独立发送器；可将人员查询本身做成单独只读服务。测试收件人、兜底代收人不得覆盖资产责任人。无员工邮箱时保留明确fallback来源，提示手动转发，同时准确说明邮件accepted/skipped/failed/unknown；没有姓名直接展示工号，不堆叠占位文案。

OA正文自动执行与机器人补Excel是两个入口时，设备重复执行和重复通知分别分析。附件未知时通知发/不发、是否新增人工复核、是否做资产去重，必须遵循用户当前选择与最新导出；不要恢复已取消的审批/数据库方案。资料不完整时不能把部分资产伪装成完整批次。

## 最小修改与交付

以最新用户导出定位稳定nodeId修改，保留已有模型、Handle、节点坐标、文件输入、URL和持久化变量机器键。不要在固定新版本提示词尾部反复追加相同规则；同一规则需要合并、去重，冲突旧规则应改写或明确替代。

如果用户已在网页配置URL/凭据而未提供当前导出，不应以旧全量JSON覆盖这些修改。提供精确字段补丁与标明基线的完整候选。拆独立查询入口时保留原监听URL，并给出停止旧重复路径、发布新监听的顺序。

验收分开报告：候选JSON、离线结构/解析检查、真实模型文件提取、平台导入回读、执行与副作用。截图显示通知阶段失败且邮件已接受时，只恢复通知，不能重跑整个准入。任何技能样例、测试数据和更新记录均使用虚拟角色、示例域名，不写本次员工资料或真实密钥。

# AI 应用与工作流架构交付

## 1. 设计产物

### 模式与触发契约

先声明主要模式和可选次要模式：`deterministic-workflow`、`single-llm`、`rag-qa`、`tool-query`、`action-approval`、`multi-tool-agent`、`event-batch` 或 `hybrid`。同时记录触发方式：对话、API、Webhook、定时或人工。知识库只对 `rag-qa` 或确需检索的混合模式必选。

### 意图路由表

先根据用户目标定义项目自己的意图，不预设行业分类。使用以下模板：

| 意图 | 触发条件与必要证据 | 确定性预路由 | 允许来源/工具 | 无命中或失败处理 |
|---|---|---|---|---|
| `<intent-a>` | `<实体、动作、约束>` | 是/否 | `<知识域或工具>` | `<澄清、回退或升级>` |
| `<intent-b>` | `<实体、动作、约束>` | 是/否 | `<知识域或工具>` | `<澄清、回退或升级>` |

常见实现类别仅用于选型，不应直接成为业务意图：

- 固定规则处理：输入和判断可以确定性表达；
- 知识检索：答案依赖受控文档；
- 工具调用：需要读取或改变外部系统状态；
- 生成任务：需要模型整合证据或生成内容；
- 人工处理：风险、权限或信息不足时升级。

### 实体与关系 Schema

根据业务定义字段，不套用固定名称。通用模板：

| 字段 | 含义 | 冲突处理 |
|---|---|---|
| `primaryEntity` | 当前请求的主要对象 | 当前轮明确对象优先 |
| `relatedEntities` | 与主要对象相关的其他对象 | 保留类型、角色和来源 |
| `relation` | 对象之间的业务关系 | 根据动词、介词和业务规则判断 |
| `parameters` | 执行动作所需参数 | 保留已提供值，只询问缺失字段 |
| `constraints` | 时间、权限、范围、格式等约束 | 高风险冲突时停止并澄清 |

具体项目可重命名字段，但必须记录实体类型、角色、关系、来源和置信度。多个实体不能退化为无标签数组。

### 能力矩阵

记录每个可选知识域、工具或外部系统支持的意图、实体类型、输入、返回字段、超时、副作用、权限和错误语义。某来源不支持请求时，不得推导为业务对象不存在或任务失败。

### 分支契约

```text
分支名称：
触发条件：
必要/可选输入：
允许数据源与工具：
证据优先级：

标准输出：
最长答案：
无命中/超时/部分成功：
禁止内容：
升级人工条件：
```

## 2. 稳定骨架

所有模式共享：触发、输入校验、分支/执行、结果校验、失败处理和可观测性。对话型应用再增加上下文与回复；RAG 增加检索与引用；写操作增加确认、幂等、回读和审计；事件/批量增加去重、限流、检查点和失败隔离。具体骨架读取 [非RAG工作流工程.md](非RAG工作流工程.md) 与 `assets/workflow-blueprints/mode-blueprints.json`。

## 3. 证据与答案

证据优先级通常为：当前轮工具/执行回读 > 当前轮确定性计算 > 当前有效上下文 > 受控知识库 > 通用模型知识。具体项目应声明例外；低优先级内容不得覆盖高优先级事实。

答案格式由使用渠道和任务目标决定。工具结果已经完整满足请求时可直接终止，不强制增加一次模型总结。隐藏与用户目标无关的来源失败、原始负载、内部实现和敏感信息。

## 4. 通用状态 Schema

```json
{
  "schemaVersion": 1,
  "lastInteractionAt": 0,
  "currentIntent": "",
  "entities": [],
  "constraints": {},
  "toolEvidence": [],
  "knowledgeEvidence": [],
  "idempotencyKey": "",
  "approvalState": "",
  "pendingFields": []
}
```

每轮刷新时间；TTL 到期和显式新话题时清理；当前轮事实优先；实体类型或角色冲突时不得静默继承；干净会话与多轮会话分开测试。字段按模式取舍，不因 Schema 示例而保存空知识、审批或幂等状态。只保存后续轮次真正需要且允许持久化的数据。

## 5. 接口与工具

- 密钥只放平台凭据系统；变量在请求体中按目标节点格式正确引用。
- 分开处理传输状态、业务状态、空结果、超时、畸形数据和部分成功。
- 只提取必要字段，设置有限超时和分支级回退。
- 给模型可选工具提供窄而不重叠的名称、说明和参数。
- 对写入、通知、删除、发布等副作用增加确认或人工审批。
- 对副作用操作定义幂等、执行回读、审计和失败恢复；对事件/批量定义去重、限流和检查点。

## 6. 发布结构

记录任务模式、触发方式、目标版本、基线哈希、工作流版本、变更节点/文档、资源重绑项、离线报告、平台回读报告、回归结果和回滚文件。使用知识库时再记录知识版本；存在副作用时增加确认、幂等和审计证据。交付包只保留可发送、可导入、可复现的材料。

# FastGPT 多版本适配

核验日期：2026-09-22。本文是任务相关的官方资料摘要和工程适配规则，不是完整官方手册，也不是全版本运行认证。

## 先识别四种版本

- 平台版本：目标服务的实际版本、构建号和社区/商业/兼容分支。以实例信息或部署记录确认；未知就记录未知。
- 节点版本：导出 JSON 内的 `version`。`481` 等标记不能用来推断服务器版本，也不能批量替换为 `4.17.0`。
- 应用版本：业务发布标签，例如 V3.5.14；`--expected-app-version` 只检查这个标签。
- 技能版本：本技能 2.8.0；开发分支内容另记 commit，不代表 FastGPT 版本。

先匹配下表中的目标版本，再读所需节点文档。滚动文档可能描述尚未发布的功能；交叉核对 [GitHub Releases](https://github.com/labring/FastGPT/releases) 和目标 tag 源码。核验时 GitHub 最新正式 Release 为 v4.17.0；文档站已有 4.17.1 页面，不能据此认为目标实例已有其修复。

## 按版本选择规则

| 目标或版本边界 | 官方证据与差异 | 构建和测试决策 |
|---|---|---|
| 旧导出 / 内置 `fastgpt-v481-minimal` | 内置模板只是离线候选，未登记服务器兼容范围 | 保留原节点 ID、Handle 和字段；不把模板命名解释为已支持整个 4.8.x |
| 4.8.9 / 4.8.13 | [文件输入](https://doc.fastgpt.io/en/guide/build/general/fileInput)：4.8.9 提供文件上传；4.8.13 调整解析和传递方式 | 区分基础模式与工作流；插件、子工作流显式传递文件，不能假设自动继承；分别测试当轮与历史文件 |
| 4.14.11+ | [并行节点](https://doc.fastgpt.io/en/guide/build/workflow/nodes/parallel_run) 标明起始版本 | 低于该版本不照搬 `parallelRun`；仍需核验节点可见性、并发上限、部分失败和重试结果 |
| 4.15.0+ | [循环节点](https://doc.fastgpt.io/en/guide/build/workflow/nodes/loop_run) 标明起始版本 | 不把新循环与历史批处理视为同一结构；检查子节点、输出、终止条件及空数组/迭代上限 |
| 4.16.0 | [版本说明](https://doc.fastgpt.io/en/self-host/upgrading/4-16/4160)：工具参数可交给 Agent 生成；知识数据支持 metadata；Agent Sandbox 生命周期变化 | 回读固定值、引用值和 Agent 生成模式；只在使用 Agent Sandbox 时检查其依赖，不与代码节点沙箱混淆 |
| 4.16.2 | [版本说明](https://doc.fastgpt.io/en/self-host/upgrading/4-16/4162)：模型配置移到管理员入口；Milvus 全文检索迁移至 BM25，其他所列向量后端不受该迁移影响 | 不沿用旧菜单定位；按实际后端设计检索回归，不向 PG 实例套用 Milvus 迁移步骤 |
| 4.17.0 | [版本说明](https://doc.fastgpt.io/en/self-host/upgrading/4-17/4170)：模型绑定标准化为稳定 ID，AI Proxy 成为必需依赖 | 按下一节检查模型键；旧 `OPENAI_BASE_URL` / `CHAT_API_KEY` 不再生效，不能把模型失败统一归因于提示词 |
| 未核验版本、预发布、兼容分支 | 不外推兼容范围或首发版本 | 优先基于真实导出做最小变更；无法访问实例仍可生成候选 JSON，明确待验证项 |

版本边界是文档证据，不保证部署已启用功能。商业版能力、权限、模型能力及外部服务仍需确认。任务只涉及工作流时，不自动执行系统升级、数据迁移或改动宿主机配置。

## 4.16 → 4.17 模型绑定

tag 级字段证据：[v4.16.2 constants.ts](https://github.com/labring/FastGPT/blob/v4.16.2/packages/global/core/workflow/constants.ts)、[v4.17.0 constants.ts](https://github.com/labring/FastGPT/blob/v4.17.0/packages/global/core/workflow/constants.ts)。这不是模型名称与 ID 的对应表。

| 用途 | 4.16.2 字段 | 4.17.0 新字段（旧字段标弃用） |
|---|---|---|
| AI 模型 | `model` | `modelId` |
| 检索重排 | `rerankModel` | `rerankModelId` |
| 检索扩展 | `datasetSearchExtensionModel` | `datasetSearchExtensionModelId` |

这些是节点 `inputs[].key`，不是要求给每个节点添加的字段。旧导出继续按旧字段检查；新版同时检查新旧键。不能把模型显示名原样移入 `modelId`，也不能因为两个字符串相同就认为迁移完成。

从目标实例选择实际模型并回导，记录旧名称 → 目标稳定 ID、用途及可用性。只映射已使用的资源。保留未知字段、隐藏配置和未修改的资源；不要通过删除字段让离线校验通过。

`validate_fastgpt_workflow.py --baseline old.json --expect-preserve-models` 的 FG102、`compare_fastgpt_roundtrip.py` 的 RT005 覆盖上述六个模型键，包含空值、动态引用和重复项。`summary.models` 是主模型摘要，完整节点模型绑定见 `summary.model_bindings`。范围仅限这些节点输入；应用级配置、其他模型字段和未来字段仍需完整差异报告及平台回读核验。

`model` → `modelId` 也属于输入结构变化：`--allow-model-change` 只接受模型值变化，不消除 RT004。核对映射并完成目标平台回归后，才把真实回导设为新基线；保留原文件以便审计和回滚。

## 版本回归最小集合

1. 同版本修改：旧键/新键各自保持不变时无误报；更换、清空或删除绑定必须能被发现。
2. 跨版本：检查节点类型、输入/输出键、边四元组、模型与知识库/插件绑定，单列预期迁移，不整体忽略漂移。
3. 按实际功能追加：文件传递、多模态模型切换、工具参数生成方式、代码节点返回/异常、循环结束与并行部分失败、RAG 引用与空结果。
4. 每个目标版本分别记录候选生成、离线、导入、回读、真实运行结果；某版本运行通过不代表所有版本通过。

目前内置模板没有新增 4.16/4.17 平台导入证据。不要复制旧模板改名充当新版本模板；取得脱敏真实导出并验证后，再登记来源 tag/构建号、哈希和验证范围。

# RAG Agent 调试手册

相信用户观察到的现象，但以目标实例的工作流、执行轨迹、接口响应和知识检索记录作为事实来源。按成本从低到高排查，不先重写整个工作流。

## 1. 最低成本检查顺序

1. 输入值与节点参数是否正确，变量类型和字符串引用是否匹配。
2. 是否使用了错误平台、错误应用、错误版本或过期导出。
3. 节点是否真实连接到预期分支，Handle 和条件是否正确。
4. 上游是否过滤或重命名了下游需要的字段。
5. 多轮上下文是否过期、未清理或被错误实体覆盖。
6. 知识库绑定、索引版本、检索域和文档版本是否正确。
7. 工具是否返回超时、空、业务错误或部分成功，而归一化层错误合并。
8. 确定性代码和提示词逻辑是否真正有误。
9. 最后再考虑平台 Bug，并使用最小工作流复现。

## 2. 按症状定位

| 症状 | 首查 | 常见根因 |
|---|---|---|
| 路由错误 | 实际输入、预路由、分类输出、边 Handle | 关键词过宽、实体角色丢失、旧上下文 |
| 查不到知识 | 原始查询、命中文档、阈值、索引版本 | 文档过长、同义词缺失、错库、旧文档 |
| 引用错乱 | 检索记录与最终提示 | 多库混检、模型手写来源、CITE 泄漏 |
| 回答过长 | 分支契约、引用量、二次生成 | SOP 自动增强、引用上限过大、提示重复 |
| 接口失败 | HTTP/业务状态、Body、Header、超时 | 变量序列化、凭据作用域、内网访问限制 |
| 多轮串话 | 状态内容、TTL、新话题检测 | 旧实体未清理、类型冲突未处理 |
| 导入后不可用 | 资源绑定、模型、变量、未执行节点 | 跨平台 ID 失效、休眠节点仍被校验 |
| 保存后结构变化 | 重导出差异 | 平台迁移、节点版本更新、全量重建 JSON |

## 3. 最小复现

保留一个开始节点、一个问题分支和一个回复节点；使用虚构输入；移除真实凭据；保存目标版本最小导出。逐步增加知识、HTTP、状态和模型节点，找到首次失败的边界。

## 4. 诊断证据

每次问题记录：平台/版本、应用模式、基线哈希、会话类型、原始输入、期望/实际路由、执行节点、脱敏工具状态、检索文档与分数、耗时、答案、错误码和最小复现文件。

## 5. 修复与回归

只修改导致问题的最小范围。修复后同时测试原失败用例、相邻负例、其他核心分支、干净会话、多轮会话和禁止输出。若修改了知识库，重建索引；若修改了 JSON，完成导入回读；若修改了接口，覆盖超时、空、业务错误和部分成功。

## 6. 不接受的捷径

- 仅因为 JSON 能解析就判断工作流正确。
- 通过扩大提示词或引用量掩盖路由/文档问题。
- 删除失败分支的错误处理以让测试“通过”。
- 在没有执行轨迹时凭节点画布猜测运行顺序。
- 将生产密钥或完整接口负载复制到调试材料。

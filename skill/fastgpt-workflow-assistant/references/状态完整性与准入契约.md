# 有状态助手、资料完整性与准入契约

用于对话式资产查询、附件批量处理和审批写入的维护。规则来自真实故障；设备类型目录、期限和网络权限属于项目配置，不是所有企业的默认政策。

## 当前意图与上下文

- 每轮先识别当前消息。历史图片、查询任务和待处理批次只是上下文，不能把“如何 Ping”“Ping 不通怎么办”等方法咨询路由为执行或旧任务续查。明确的当前命令才调用工具；含糊问题先解释最可能的问题，追问一个关键点，并检索相近知识。
- 区分学习方法、排查故障、立即执行。诊断须区分源到目标 ICMP、业务 TCP/UDP 端口和目标 Windows 入站防火墙；Ping 成功不证明业务可用，超时不证明设备离线。按企业流程申请所需策略，不默认让用户关闭全部防护。
- 多轮修改资料保留当前完整资产清单、人员、整批属性和行来源。资料确认、执行确认、执行中、结果未知分开；资料范围确认只能回到预览，不能直接写入，也不能误复用旧批次确认。

## 完整性按证据判断

- “无空白行、截断、乱码或解析错误”是并列否定，不能只命中关键词就报附件异常。按分句及转折识别肯定证据；“无乱码，但第二张表未读取”仍有真实缺失。
- 没有文件输入的粘贴 Markdown 表格不能被历史附件标记判为未读取。基于当前可见行和结构化解析状态重新计算缺项，不回抄上一条机器人错误提示作为新证据。
- 没有阻碍实际接口的缺项时，直接生成完整执行预览，省去单独“资料是否完整”来回。用户“确认无需补齐”等表述可以更新范围状态，但不构成准入写入授权。
- 真正的截断、解析失败、未读文件/工作表、行数不符及关键字段冲突仍须指出具体位置；用户口头确认不能修复损失。未知范围可并入已有整批执行确认，不应制造无限问答循环。

## 类型与期限贯穿实际写入

- 使用平台实际导出的标准目录和项目字段契约。语义理解给候选，确定性映射填标准全称；别名唯一时补全，有歧义再追问。目录名称、组标签与 API 类型 ID 不互换。
- 检查提取、预览、编码、HTTP 请求及每个最终写入分支。前端显示标准类型不等于后端已经采用。例如项目使用 `fields.form[].requested_ttype` 时，必须在请求校验和所有写入分支保留它。
- 显式有效类型优先于设备名称、备注、Windows 标志、MAC 厂商等旧推断；在最终 payload 的赋值点检查覆盖顺序。显式非法类型应在副作用前报错，不能偷偷回退推断；未传值时才沿用旧规则。
- 有效期从最终类型及该项目政策计算，并保留既有“保留注册状态”例外。区分空期限（永久）、不发送期限（保留原值）与实际日期；不能把三者混为一谈。不擅自把“365天”改成“下年同日”。时间戳与展示时区分开，避免宿主时区造成重复加八小时。
- 回归应执行生成的最终 Code/编码逻辑：显式类型与名称/OUI 冲突、全部写入分支、有/无类型、无效类型、批量一行非法、永久与期限切换。仅看预览不算验证写入契约。

## 资产响应的语义单位

- 查清 HTTP 原始响应→整理 records/facts→权限投影→最终渲染在哪层丢字段。火绒一类嵌套响应应以终端父记录为设备，不能把命中 MAC 的 netconf 子网卡当整机，否则名称、系统、资产信息全部丢失。
- 多网卡以成对的 IP/MAC/掩码/网关/DNS 展示；不把不同网卡的字段交叉拼接。IP 列表支持中文顿号、分号等真实分隔符，匹配应对标准化地址逐项比较。
- 最后上线、最后在线、最后发现、更新时间是不同事实。字段含义未证实时不猜；原接口没有就修上游保留真实字段，不用查询时间替代。
- 成功且明确空结果才是未匹配；超时、异常、未知结构、部分响应分别保留原因。不要统一包装成未安装或未匹配，也不要把有真实成功空证据的响应永远称为返回不完整。
- n8n HTTP 失败分支后普通 Code 节点成功，只说明处理错误成功，不证明接口查询成功。关闭会制造空成功帧的 alwaysOutputData 时检查连接；错误原因跨整理节点保留。超时按上游耗时和整体预算调整；写入/通知不能默认自动重试。

## 展示、文件与发布

- 企业微信采用已验证的两列单设备表/三列批量表；单元格逐字段换行，表头前留空行，转义原值后插入受控换行。保留名称、别名、类型、责任人、地址、在线及准入等有用字段，不为简短而只剩状态。单记录省略计数，多记录才标数量。
- 平台显示过滤按助手身份配置，不从共享查询层删除其他助手需要的数据。不支持的平台可隐藏；无匹配是否展示遵循用户要求。项目不支持结果文件时仍保留 Excel/CSV 输入；同一物理行的有效 MAC 优先于 IP，不能跨行拼设备。
- GitHub 公开技能只包含抽象规则和虚拟例子。业务工作流进入指定私有仓库前仍清除密钥、Token、签名 URL、固定运行输入；凭据引用留重新绑定说明。原始文件本地保留，发布副本的清理差异有清单可追溯。
- 固定本地“最新候选”指针和基线哈希，分别记录离线、目标实例导入、运行、上线状态。候选快照上传 GitHub 不是在线发布；不要凭文件日期宣称目标实例已经使用。

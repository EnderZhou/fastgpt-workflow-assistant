# 四模型实测后的构建与验收规范

## 技能入口与版本
先定位当前专家根目录及隐藏 `.codebuddy-plugin/plugin.json`，读取其声明的内置 SKILL.md 与 assets/skill-version.json。记录专家和技能两层版本，不把技能发布器当工作流生成技能，不以全盘搜索中版本最大者替代当前实际调用入口。独立技能模式只报告实际技能，不虚构专家信息。

## 意图、地址与目标完整性
用于 IP/MAC 资产查询时，先识别用户的显式 ping 意图，再独立校验参数。缺IP、MAC或多目标应明确提示，不静默降级成资产查询；多目标ping按用户契约决定，不能只取首条。中文插入词、中文紧贴地址与标点应在用例中覆盖；ping10等连写是否支持按当前需求决定，不擅自扩大触发范围。
逐个校验完整疑似地址词元，禁止从五段IP、超长数字或非法MAC截取合法子串。普通自然语言不等于非法资产；疑似地址须有有效、重复、非法/不完整或未处理的归宿和原因。前导零及特殊地址范围按项目约定处理，文档和实现一致，不把示例拒绝规则当全局业务策略。
不增加未经要求的单目标、数量或仅内网限制。合法目标可按需求继续处理，其他目标不能静默丢弃。

## 请求执行与结果对账
多目标提取通过不代表多目标查询实现。接口支持批量须有契约证据；仅支持单查则循环全部目标，不能仅取首项。未知契约保留未就绪状态，并明确请求映射为待确认。每个结果保留请求目标身份；乱序返回按身份对账，无标识不强行按顺序分配。覆盖末项、部分失败、重复目标及结果缺项。
未配置时以HTTP前门禁拦截，不依赖空URL、localhost、占位域名或解析错误保证零请求。用 check_route_contract.py 检查门禁出口全部后续连线；这只证明图隔离，不证明条件值或平台实际零请求。URL、鉴权、请求/响应映射及错误语义配置并测试后，最后启用开关。
HTTP catch配置、错误输出及catch边以目标基线为准；未配置、超时/403、空结果、业务不存在分别记录，不把错误写成成功或空资产。

## 校验与证据
validate_fastgpt_workflow.py 新增有限结构诊断 FG090–FG094：已知误写节点/键、条件分支handle、catch启用和输出契约。可用 --schema-baseline 对照目标导出节点类型；这是有限schema核对，不是全平台schema认证，未知扩展不能凭main源码判死。
行为测试用 scripts/run_code_contract.js 从最终JSON提取代码；合同由用户需求定义，用 expected 精确子集与 forbidden 明确禁止值，不能把实际输出倒填成期望。样例 assets/asset-query-behavior-contract.json 的节点映射可改，期望改变需需求依据。该脚本执行代码，只用于已审查可信候选；禁用网络/模块入口不等于安全沙箱，不能用于执行不可信第三方代码。
强制反例：裸ping、ping+MAC、多目标ping、中文紧贴地址、中文插入词、不完整地址、五段IP、非法MAC混合法目标、去重、超过旧示例数量限制。保存命令、退出码、stdout/stderr、最终JSON与合同哈希；测试失败须非零退出。
静态图、代码行为、平台导入/回读、实际循环执行、真实接口分别报告。循环容器和循环体分别做静态合同；必要时用故意误连、删线、错误输出证明检测器会失败。可达不等于必经，断言数量不代表覆盖质量。

## 模型选择备注
测试时固定提示词、技能/专家版本、资料和思考设置，记录模型界面全名、耗时和首轮/辅助修复阶段。免费额度影响可用性，不等于质量。当前证据不足以指定唯一首选模型；跨模型发现应转成通用合同和反例，不写未经验证的模型优劣排名。

## 本地执行示例

```text
python scripts/validate_fastgpt_workflow.py candidate.json --schema-baseline baseline.json --strict --json
node scripts/run_code_contract.js candidate.json adapted-contract.json behavior-report.json
python scripts/check_route_contract.py candidate.json route-contract.json
```

行为合同的节点名、入参名和输出字段需按最终JSON映射；例如 route=ping_missing 可映射到实例的其他等价状态，但必须保留“显式ping缺IP，未执行请求”的预期。更改映射不等于放宽业务断言。合同执行器只检查代码输出，接口配置开关的两种状态与实际分支需另外做路由测试。

## 3.0.2 本地修订 local-r2：数据接线与回复完整性

同一版本的本地测试包通过 assets/skill-version.json 的 local_revision 区分。local-r2为此前修订；当前值读取版本清单。报告专家版本、技能版本、修订标识和包哈希。不能只看到3.0.2就断言已加载本次修订。

### 入参必须在交付JSON中接线
`system_addInputParam` 是添加参数的控件，不是实际参数。代码签名 `main({input})` 对应真实inputs条目 `key=input` 并绑定 `[workflowStartNodeId,userChatInput]`；门禁同理绑定解析输出和 `[VARIABLE_NODE_ID,变量key]`。全局变量仅声明、不绑定到代码输入，不会自动进入函数。
校验新增FG095（平面main必需参数缺声明）、FG096（声明缺值/引用结构错误）、FG097（HTTP输出契约）。签名检查仅覆盖可可靠识别的平面JS解构，复杂签名无诊断不代表已检查；必须补bound执行合同。

### 测试分为独立函数与绑定数据链
`run_code_contract.js` 保留默认direct模式用于函数级测试；此模式手工传参，不能证明接线正确。
`mode=bound` 从最终JSON的inputs构造参数，`seeds`仅提供已声明上游输出，`variables`覆盖已声明全局变量；不允许再提供input绕过接线。引用按output.id解析到实际输出key。`required_inputs`要求关键参数已声明。未声明/未解析引用、用seed冒充执行节点必须失败。
多个 `steps` 是合同明确指定的数据处理步骤，可以运行已审查代码和本地answer文本替换；它不代表真实运行路径，不求值ifElse、不运行HTTP和循环。路由仍需静态合同与平台验证。HTTP模拟响应仅能作明确标记的上游种子，不代表真实接口已返回。
使用 assets/asset-query-behavior-contract.json 检查解析，用 assets/execution-binding-contract.example.json 检查门禁和最终回复。必须按目标字段映射，不通过删掉失败期望使合同转绿。

### HTTP声明不等于平台产出
候选自行声明 `system_httpResponse` 并引用，不证明平台会产生该字段。按schema基线核对静态输出，常见httpRequest468原始响应为httpRawResponse；合法动态字段提取须依据真实契约保留。其他实例确有不同导出时使用其实证，不强制跨版本硬编码。
门禁和HTTP实际URL使用同一配置源；无效字符串不能表示就绪。就绪还取决于鉴权、请求响应映射及契约完成，不能仅用非空URL代表全部完成。不把localhost当通用禁用规则，地址范围按用户部署约定。

### ping与完整地址
显式ping不能用 `/ping/i` 子串检测。至少覆盖 mapping、shopping、pinging 等不触发，以及PING、中文插入词可触发；连写按用户契约单独决定。非法目标不能经删除字符后变成另一个合法目标，七组MAC、超长IPv4原词元须保留并报告。

### 最终回复是验收对象
解析数组含非法项不等于用户已看到原目标及原因。对invalid、部分合法、未配置、ping参数错误等出口执行最终回复合同，用 `contains_all` 验证原值和原因，配合 `required_references` 确认回复确实引用动态业务字段。对象/数组采用本地JSON序列化只是离线近似，实际平台展示仍待验证。
“五段IP不截取”用例同时断言无合法目标、invalidTargets保留完整原值及原因；只检查route=invalid/targetCount=0会漏掉静默吞地址。
变异先确认制造了预定故障，再要求指定用例以预定错误失败；其他用例因副作用失败只能记为副作用捕获，不能宣称目标缺陷被验证。原始失败记录与修复后记录均保留，不清理唯一证据。

实际字段片段参照[输入输出绑定示例](../assets/input-output-binding.example.json)；该文件不是导入式工作流，不得只复制添加控件而遗漏真实输入。bound执行器当前仅支持同步JS main、明确的数据步骤及简单answer文本替换，异步main会明确返回未支持，不能冒充空对象测试通过。

## 3.0.2 本地修订 local-r3：就绪、同源与异常完整性

local-r3继续使用3.0.2版本号，通过版本清单local_revision区分。

### URL语法与接口就绪必须分开
禁止只匹配 `^https?://` 就判定就绪。至少校验协议、非空合法主机、端口、空白/控制字符和凭据；http://、https://???、https://:443、端口越界及TODO标记必须失败。离线 `check_http_contract.py` 的validate_url仅检查语法，不解析DNS、不访问接口；example.invalid语法合法不代表可调用。localhost及内网IP按用户部署约定处理，不默认封禁。
候选运行时代码必须独立测试相同反例，不能用离线Python检查通过替代运行时门禁。代码沙箱若没有URL解析器，应使用目标环境支持的实现，或保持接口不可启用并标明待配置，不猜测全局URL对象存在。
就绪还要求真实接口契约、请求/响应映射和鉴权配置完成；URL合法不等于契约完成。先配参数和响应映射、测试并回读，最后启用调用。

### 配置同源与能力取证
门禁与HTTP实际请求地址必须来自同一个配置。优先使用目标导出已证实的引用机制；若实例只支持固定地址，可由一个受控配置在构建时同时生成门禁和HTTP字段，回读并核对两处值。
“字段hidden、基线全是固定值”只能说明没有引用示例，不能推出“不支持变量引用”或“UI支持但导出无法表达”。这两类能力均需目标实例回导或对应版本源码证据，未知时保持待验证，不能用说明文案替代实现。
使用 assets/http-execution-contract.example.json 映射目标节点；运行：
```text
python scripts/check_http_contract.py candidate.json http-contract.json
python scripts/validate_fastgpt_workflow.py candidate.json --schema-baseline baseline.json --http-contract http-contract.json --strict --json
```
合同核对门禁输入与HTTP URL的导出值/引用来源、变量声明及直接catch接线；集成诊断FG098。相等引用不证明平台实际解析该引用。字段为空或不同源须失败；契约尚未确认时只交付默认隔离的候选，不能宣称执行完成。

### 完整词元和显式ping
捕获疑似IP时不要先用每段1至3位限制截短原词元。先保留完整连续数字点分序列，再按四段及0至255校验；1192.0.2.1与192.0.2.1234必须按原值报告，不能变成0.2.1或直接消失。还应检查地址与英文、数字、点的相邻边界，避免匹配中间子串。
按当前资产查询示例的单目标ping约定，ping输入混入任何非法/不完整疑似目标时，明确拒绝并列出原值和原因，清空ping目标，不选唯一合法项继续检测。普通资产查询合法项部分处理策略保持不变；其他项目按用户明确契约制定。

### HTTP异常兜底
HTTP超时、401/403、5xx、畸形响应、空结果、未配置、业务未找到分别定义。catchError、error输出和source_catch边按基线绑定；不能让错误走正常成功回复，也不能把错误说成“未查询到资产”。错误处理需保留目标身份，脱敏日志保留技术详情，不把完整凭据/原始错误暴露在用户回复。
HTTP配置合同只查直接catch连线及显式引用，复杂下游须结合check_route_contract.py遍历全部分支；文本错误语义仍用bound合同验证。模拟响应必须标记，不调用真实HTTP。
assets/http-failure-behavior.example.json用于模拟超时/403后的最终回执；assets/code-snippets/http-result-state.js为可调整的状态归一化片段，statusCode等字段必须按真实契约映射，received不等于业务成功。

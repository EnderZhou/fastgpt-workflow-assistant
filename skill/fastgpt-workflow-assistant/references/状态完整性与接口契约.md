# 有状态助手、资料完整性与接口契约

用于维护多轮对话、文件处理、工具调用及写入流程。只包含跨业务通用的工程原则；具体枚举、参数优先级、业务期限和权限由目标项目定义。

## 当前意图与上下文

- 每轮先判断当前消息是方法咨询、故障求助、查询请求、补充资料还是执行指令。历史工具任务只是上下文，不能把新咨询强制路由到旧任务。
- 模糊问题先给出有依据的解释，再追问一个影响下一步的关键点；检索相关知识，不虚构工具结果。判断“询问如何做”和“要求立即做”，依照目标工具实际副作用处理授权。
- 将草稿、待确认、执行中、结果未知和完成分开。补充资料保留当前完整清单与来源；确认绑定当前对象、动作和参数。资料范围确认不等于写入授权。

## 完整性按证据判断

- “无截断、乱码或解析错误”是并列否定，不能只按缺陷关键词判失败。按分句和转折识别肯定证据；“无乱码，但第二张表未读取”仍有实际缺失。
- 没有附件的粘贴表格不能因历史附件标记被判为未读取。依据当前可见内容和解析状态重新计算缺项，不能回抄上轮机器人错误文案作为证据。
- 没有阻碍真实接口的缺项时，进入正常预览或下一步，不单独反复询问资料是否完整。实际截断、未读文件或工作表、数量不符和关键字段冲突需指出具体位置；口头确认不能修复真实数据损失。

## 字段贯穿实际接口

- 根据目标 API 和最新导出确定字段类型、必填项、允许值与覆盖顺序，不从其他项目移植枚举或业务规则。
- 检查提取、预览、编码、HTTP 请求和最终写入分支。前端展示了某值不证明接口收到该值；应在实际请求构造点核验。
- 区分未提供、空字符串、null、false和0，按真实接口语义决定默认值与更新行为。明确优先级后检查后续节点是否覆盖用户输入；不让模型臆造优先级。
- 测试最终生成逻辑与真实参数结构，覆盖缺省、显式值、无效值、冲突及批量部分失败。离线模拟通过不等于平台导入或真实接口通过。

## 嵌套响应与错误语义

- 沿原始 HTTP 响应、结构化整理、权限投影和最终渲染逐层定位字段丢失。先定义记录的语义单位，不把嵌套子项误作完整父记录；一对多关系保留关联。
- 复杂字段按实际结构规范化，保留来源路径和对应关系；不同字段、不同来源及不同记录不能交叉拼接。
- 创建、更新、发生和查询时间等含义分别保留；没有真实字段就说明缺失，不用当前时间代替。存储时间戳与显示时区分开处理。
- 成功且明确空结果、接口异常、超时、未知结构和部分成功分别报告。错误处理节点成功只表示已处理错误，不证明上游业务成功。
- 超时预算根据完整调用链调整；重试根据幂等性与副作用决定，不能因读请求允许重试就自动重试写入或通知。

## 展示与交付

- 根据用户渠道验证表格、换行和消息长度。精简展示不得删除用户需要核对的信息；展示过滤不应破坏共享数据或执行载荷。
- 文件输入与结果文件交付分别配置。用户取消下载能力时，不应连带关闭仍需要的上传和解析能力；关联键和去重方式按目标数据契约决定。
- 分开记录候选JSON、离线验证、目标实例导入、运行及上线状态。分发前清理凭据、固定运行输入和真实日志，记录来源与哈希，说明重新绑定项。

# 免登录窗口测试与引导

适用于用户已导入工作流、发布分享页面，或提供免登录窗口URL要求验收的情况。与接口自动化回归互补，不替代导入回读和执行详情。

## 主动引导时机
用户确认“导入成功”后，若当前范围包括验证/优化，主动建议到应用的发布渠道使用免登录窗口进行测试，请用户提供分享URL，并确认发布渠道指向刚保存的版本。不要要求用户把应用改为公开或关闭密码；已有受控分享渠道即可。提供分享链接不自动授权压力测试或工作流中业务写入。
如果用户只是问怎么操作，给出简短步骤与可复制测试任务；若已经要求测试该URL，则在现有授权范围内继续，不为普通只读功能测试重复确认。默认未就绪门禁保持关闭，不为测试方便启用真实业务接口或修改发布配置。

## 入口核对与文件角色
1. 核对真实专家、技能版本与local_revision，读取当前JSON及用户提供的目标URL。区分用户已验证的导入状态和专家实际观察结果。
2. 分享页面的发布版本可能落后于编辑草稿。记录页面标题、URL、测试时间、用户确认的发布版本、工作流SHA256。无法核对分享渠道与文件的一致性时标为待验证，不能只凭本地哈希认定线上已更新。
3. `shareId`不是`appId`，页面URL不是聊天接口URL。仅从实际页面公开请求、目标文档/源码或用户配置确认端点与请求体，不猜供应商后缀、接口路径或鉴权。
4. 可运行 `prepare_share_window_test.py --page-url <URL> --workflow <JSON> --output restricted/target-report.json` 保存离线目标清单。该脚本不联网，输出是报告，不能导入工作流；不能把prepared当在线测试通过。额外带token/密码参数的URL先人工处理，不复制进报告。

## HTTP/API优先，浏览器降级
用户于本地测试明确反馈浏览器逐条操作耗时且消耗上下文。默认使用HTTP/API执行功能回归，浏览器只用于协议取证受阻后的辅助观察或用户明确要求的页面排版检查。不要每条测试都截图或操作输入框。

用户已提供分享URL并要求测试，已授权该范围的只读页面/公开脚本读取、必要的协议取证和约定的测试对话。无需再次询问“是否允许打开页面”，也不能把“缺聊天API契约”当作整个任务不能开始的理由。先用已有工具推进可做的取证；禁止猜接口不等于禁止主动发现接口。

执行顺序：
1. 接收URL后核对实际专家/技能入口与当前任务；发现可用HTTP客户端、执行终端、已有分享接口工具及网络能力。不要假定客户端一定有浏览器或某个MCP工具。
2. 先按[分享URL直接回归入口](分享URL直接回归入口.md)查询本机注册表、项目配置及历史成功调用。同实例有证据时复用协议直接冒烟，不必重新抓包或解析页面。无协议证据或实际调用表明变化时，才通过普通HTTP GET读取分享页面、可公开访问的初始化配置与页面引用脚本，或查阅本实例对应的官方文档/公开源码，找真实接口路径、方法、请求体、shareId传递、流式协议和必要鉴权。按实际引用和证据链阅读，不盲扫路径，不读取Cookie/密码/本地存储，不绕过访问控制。平台标准协议可作为有版本和来源依据的候选，不能只凭同名平台硬套。
3. 保存来源URL/本地文件、时间、证据片段和哈希，确认页面地址与聊天接口的区别、shareId/appId字段和请求体。证据足够后复用run_share_api_regression.py直接发请求；分享模式核对--share-only，不臆造appId、不无依据索要API Key。第一次只跑一个低影响冒烟用例，确认协议和SSE可解析后再执行已批准用例集。
4. 独立用例新chatId/outLinkUid，同一多轮用例复用，单并发、响应结束后至少间隔3秒。保存首次失败及原始响应到本地受限目录；对话中只给进度与简短汇总，不反复粘贴完整页面、脚本或SSE，降低上下文开销。不得自动开启契约未就绪的真实资产/ping接口，也不做压力测试。
5. 只有HTTP取证无法确认协议、网页必须执行脚本才能继续、或用户要求验证排版时，才用实际可用浏览器辅助获取协议/展示证据。既有测试授权不需再次询问只读打开页面，除非出现新的权限、访问码或动作范围变化。协议已确认后回到API批量回归，不逐条GUI操作。
6. 仍受阻时报告实际尝试的工具、失败层级及缺少的最小信息，给出可选的手动取证步骤。只有确实无法自行获取时才请用户提供接口文档/请求样例或完成登录；不以固定“三选一”重复索要API契约，不把工具不可用说成用户未授权，也不编造已请求/已通过。

普通HTTP请求返回HTML并不等于已经测试聊天；prepare_share_window_test.py仅离线准备。页面可访问、接口响应、节点执行详情和可视展示须分别验收，API正确不能证明页面排版正确。访问受限时保留证据，不自动切换站点或发送到第三方代理。

## 用例按真实应用生成
先根据需求、JSON及线上配置整理输入/预期/必经节点/禁止节点/证据来源，再测试。普通工具查询不要加知识库或模型要求。
对于默认禁用接口的资产查询示例，可覆盖欢迎语、普通IP、中文紧贴IP、混合多目标和去重、五段/超长IP、非法MAC、显式ping缺IP/多目标/混非法项，以及mapping等不触发ping。合法目标应进入相应未就绪提示；非法输入应明确说明问题。接口已配置时重新制定预期，不能套用未配置回复。
同一多轮用例保持会话，独立用例使用新会话/测试标识，不清空其他用户的会话。使用合成目标，避免把业务数据放进公开测试说明。链接能访问不代表外部工具一定能访问公司网络。

## 五层证据分别报告
- 页面：是否打开、欢迎语和排版是否正常。
- 对话：每条原始输入、实际答案、预期、耗时、首轮是否失败。
- 执行：实际节点、分支、错误和HTTP记录。分享页看不到运行详情时标“不可观察”，不能根据“接口未配置”的文案证明零HTTP；引导用户提供后台对应轮次的执行详情或导出日志。
- 版本/回读：分享发布版本与目标JSON是否一致，导入后结构是否保留。
- 接口：真实业务调用是否执行、错误/空响应/身份对账是否正确。门禁关闭时本层未执行，不把它算作接口成功。
后台日志默认导出范围通常为最近7天（目标实例为准），主动引导用户按本轮时间定位，必要时扩大日期范围以增加分析数据；原始日志按受限资料保存，不公开。
记录网页观察/接口响应/后台执行详情/用户转述各自来源。缺执行详情时只能验收可观察的页面和答案，不能证明隐藏分支、未调用ping或零请求。

## 故障闭环与交付
发布版本未更新、页面不可达、空答、代码沙箱错误、变量引用缺失、门禁失效和排版问题分开分类。先保存首次失败；只读取证能推进时继续，不反复要求整份导出。用户已授权修复则生成独立候选，重新离线检查；发布/线上导入另按当前明确授权，不自动覆盖。
最终交付优先链接唯一“工作流导入JSON”；测试报告、用例合同、目标清单独立目录并标不可导入。机器清单记录artifact_role、路径、哈希与验证阶段，防止再次将核验报告当配置导入。
本地包修改不会自动更新WorkBuddy安装目录、应用草稿或发布渠道。已导入不等于已发布；已发布不等于已实际运行；部分用例通过不等于全功能验收。

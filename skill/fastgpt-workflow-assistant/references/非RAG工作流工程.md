# 非 RAG 工作流工程

## 1. 模式判定

先确认业务结果依赖什么，不因平台名称包含 RAG 就默认增加知识库。

| 模式 | 主要依据 | 推荐实现 | 首要风险 |
|---|---|---|---|
| 确定性流程 | 固定规则与字段 | 条件、代码、普通工作流 | 规则遗漏、边界输入 |
| 单模型任务 | 一次生成、分类、提取或改写 | 单 LLM + 结构化校验 | 格式漂移、幻觉 |
| 只读查询 | 外部系统当前状态 | HTTP/API + 归一化 | 权限、超时、空结果 |
| 审批写回 | 改变外部状态 | 预览 + 确认/审批 + 幂等执行 + 回读 | 重复写入、越权 |
| 多工具 Agent | 自然语言动态选择工具 | 小而互斥的工具集 | 误选工具、无限循环 |
| 事件/批量 | 定时、Webhook、消息或数组输入 | 去重、分批、限流、断点续跑 | 重复事件、部分失败 |
| 混合编排 | 多种依据共同存在 | 局部模式组合 | 边界不清、过度 Agent 化 |

如果固定路由、代码或普通工作流能够稳定完成，不使用 Agent。只有答案依赖受控文档时才使用知识检索。

## 2. 设计契约

非 RAG 项目至少形成：

```text
主要/次要模式：
触发器：对话|API|Webhook|定时|人工
输入 Schema 与校验：
输出 Schema 与消费者：
外部系统与权限范围：
副作用：none|read|write|notify|delete|publish
幂等键与重复触发行为：
超时、重试与退避：
部分成功与补偿/人工恢复：
并发、速率与批次上限：
审计字段与保留期限：
```

## 3. 只读查询

输入先做类型、范围和权限校验。区分传输错误、无权限、不支持、业务对象不存在、空结果、部分成功和超时；不得把其中一种解释成另一种。把不同接口返回归一为稳定业务状态后再交给模型，确定性结果完整时直接回复。

## 4. 写入、通知与审批

- 在执行前展示将要改变的对象、字段、范围和不可逆影响。
- 只有当前轮明确确认或有效审批令牌才能执行；历史会话中的“确认”不能跨对象复用。
- 使用业务幂等键，重复提交返回原执行结果或明确拒绝，不重复写入或通知。
- 执行后回读目标状态；“请求已发送”不等于业务成功。
- 记录请求人、审批人、时间、对象、变更摘要、幂等键和结果；日志不得保存密钥和不必要的敏感负载。
- 没有可靠补偿时，失败分支升级人工，不自动尝试相反写操作。

## 5. 事件与批量处理

- 定时或事件任务通常在启用任务、扩大范围或改变副作用配置时审批，不要求每条事件都进入对话确认；运行时仍必须限制授权范围并保留审计。
- 为事件使用来源 ID 或业务键去重；明确重复事件是忽略、合并还是重新计算。
- 大数组分批，设置最大批次、并发和速率；保留成功、失败和待重试集合。
- 重试只针对可重试错误，使用有限次数和退避；业务校验失败不得无限重试。
- 使用检查点或游标支持断点续跑；重新运行时不得重复已成功副作用。
- 汇总中分别报告总数、成功、跳过、失败和待人工处理，不用单一“完成”掩盖部分失败。

## 6. 多工具 Agent

工具名称、描述和参数要窄且互斥；高风险工具与只读工具分开。给 Agent 设置最大步骤、终止条件和无工具回退。能通过实体或命令确定路由时先走确定性预路由；工具结果足够时直接终止，不强制模型二次总结。

## 7. 测试门禁

- 确定性流程：边界值、缺字段、冲突规则、不可达分支。
- 单模型：JSON/字段 Schema、长度、禁止内容、低置信回退。
- 查询：无权限、不存在、空、超时、畸形、部分成功。
- 写入：未确认不执行、重复确认、重复提交、回读不一致、部分失败。
- 事件/批量：重复事件、乱序、分批边界、限流、断点续跑、失败隔离。
- 多工具：误选、冲突、无工具、工具异常、最大步骤和终止。

测试副作用节点必须使用非生产资源并取得用户明确授权。无法安全执行时，交付模拟结果和待验证清单，不宣称运行通过。

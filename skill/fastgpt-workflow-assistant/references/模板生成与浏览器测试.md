# 模板生成、导入与持续优化

## 1. 不以用户导出作为新建前置

新建 Agent 时先收集业务需求、平台和已知版本，然后直接选择模板生成 JSON。只有以下条件同时成立时才请求用户导出：没有可用或兼容模板；无法通过浏览器/API访问测试平台；已有导入错误、截图和日志仍不足以定位。

## 2. 模板选择

读取 `assets/workflow-templates/catalog.json`，按平台、应用模式、Schema/节点版本和验证状态选择。优先级：目标版本导入验证通过 > 目标版本结构验证通过 > 兼容版本模板 > 最近模板候选。

先读取 `assets/workflow-blueprints/mode-blueprints.json` 选择逻辑模式，再选择目标版本 JSON 模板。模式蓝图只说明节点职责、风险和测试要求，不可直接导入；不得为了套用 RAG 模板而给非知识项目增加知识库。

内置最小模板只负责提供目标版本结构的起点。根据模式按需增加分类、知识检索、AI、HTTP、代码、条件、审批、循环/批量、状态和回复节点；资源 ID、模型和凭据保持为空或占位符，由目标实例重绑。

生成起始 JSON：

```powershell
python scripts/create_workflow_from_template.py output.json --welcome-text "欢迎语" --reply-text "初始回复"
```

生成后运行工作流验证器。模板版本与目标版本不同或模板未做目标平台导入验证时，将结果标记为“候选可导入 JSON”，仍应交付给用户尝试导入。

## 3. 浏览器辅助导入与测试

用户授权、浏览器能力可用且平台页面可访问时：

1. 使用用户指定浏览器；未指定时使用可用默认浏览器。
2. 进入非生产测试应用，不检查 Cookie、本地存储、密码或会话文件。
3. 导入候选 JSON并读取页面显示的校验错误。
4. 绑定用户明确授权且实际使用的模型、知识库、插件和测试资源；不查看或复制已有凭据值。
5. 保存并重新导出，执行 Round-trip 比较。
6. 按任务模式运行对话、API、事件或批量用例，记录输出、路由/分支、引用、工具状态、回读、耗时和截图。
7. 写入、通知、删除、发布或其他副作用节点必须先取得用户明确授权；默认不在生产应用执行。

文件输入工作流还要执行专门回读：确认 `chatConfig.fileSelectConfig`、开始节点 `userFiles` 输出、判断条件和所有文件链接引用均存在。若导入后界面显示“选择引用变量”，先保存上传配置使上游输出生成，再重绑下游；详细规则见 [文件输入与多文件审核](文件输入与多文件审核.md)。

认证阻塞时要求用户在同一浏览器完成登录并告知已就绪，不切换平台或绕过登录。

## 4. 用户自行导入时的反馈闭环

首次交付同时提供 JSON、绑定清单、导入步骤和测试用例。请用户返回最小必要反馈：完整错误文字或截图、平台/版本、失败步骤；运行问题再补充原始问题、实际答案、期望答案、引用和耗时。

处理反馈：

1. 把失败现象转成回归用例。
2. 判断是 Schema、资源绑定、路由、检索、工具、上下文还是展示问题。
3. 最小修改节点或知识文档。
4. 重新执行离线验证和相关回归。
5. 输出新版本 JSON及差异说明。
6. 重复直到达到验收条件。

不要让用户为了每轮优化重新导出完整工作流；已有 JSON、错误证据或浏览器回读足够时直接迭代。
